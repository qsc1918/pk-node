画笔算法

弧线模式遇到非 > / < 的题会自动回落七段码。

出题撞频控（HTTP 400「请求过于频繁」）时会按上面的间隔自动重试，累计超过「最长等待」才判该轮失败。
服务端有约 60 秒的账号级出题冷却（实测仍在）—— 「每轮间隔」默认填 0，意为不等，改由「出题频控重试」在背景里蹲冷却。
实际耗时由「出题频控重试间隔 × 默认出发题轮数」决定（默认 10s×最长 12 次左右）， 比硬等 60s 短得多 —— 这正是上面那个「填入推荐值」按钮做的事。
注：刷练习没有这个冷却（那边约 1 秒），两边的「每轮间隔」不要互相套用。

任务之间没有并行数量限制（可同时挂任意多个任务，都会出现在「任务」页）； 每个任务内部仍是逐轮串行。

批量开任务（多个账号 · 同一套配置）

勾上多个小猿账号再点「批量开始」—— 每个账号各起一个独立任务，共用上面这套参数。 任务之间互不干扰：各自独立计数、可单独暂停 / 继续 / 停止，在「任务」页统一管理。

实时日志

PK 页面（原版 H5 容器）

这是原版 PK 页面本身 —— 由服务端把 H5 整套（HTML + 资产）从 CDN 代理到本机同源， 并注入 XHR hook 把 H5 的 API 请求改写到本机，由 Node 侧补 sign / 风控头 / _productId=631 后用该账号 cookie 转发。
所以 H5 全程无感（它以为在直连主域），我们拿到了完整登录态与风控头 —— 这正是浏览器直连做不到的。

（勾选后点「打开 PK 页面」生效；页面内不再显示悬浮窗）

三个开关分别做什么：
· 视为正确答案 —— 手写识别那一步直接回「本题的标准答案」，所以一定会判对。 浏览器里没有手写 OCR（那是 App 离线模型的能力），因此不勾这个开关时， 手写任何符号都会判错，别把它当 bug。
· 自动提交画笔 —— 自动在画板上写一笔并抬手（等于替你交卷），配合上面的开关即「全自动答题」。
· 自动下一局 —— 结算页自动点「继续PK / 再练一次」，一局接一局地刷。
三个开关会随页面跳转一路带下去（pk → 对局 → 结算），不用每页重设。

经验上报（刷分）

POST /leo-star/android/exercise/rank/login/attend（gzip + 内容编码）。
每个 ruleType 每天只记一次；实测可记账的只有 0 与 1， 单次上限 200 ⇒ 日上限 400 分。同一类型当天再报会返回 200 但不加分（服务端静默去重）。 


    


    

      
自动刷练习（出题 → 抄答案 → 提交）

      

        完整闭环：POST /leo-math/android/exams 出题（每题自带 answer）→
        PUT /leo-math/android/exams/{examId} JSON 明文提交（含笔迹 script，服务端凭笔迹判卷）。
        经验 = 答对题数 × 2（10 题 20 / 100 题 200）。

        练习链路的出题冷却实测约 1 秒/账号（2026-10-01 复测：连续出题 4 次全 200）——
        注意「刷局（PK）」完全是另一回事：那边有 ≈60 秒的冷却，别把这里的数字套过去；
        引擎贴着冷却自动配速，撞频控（429）会自动重试。建议 limit=100（一轮 200 经验，约 1.5 秒）。
      

      

        
        
        
      

      

        
        
      

      

        每轮间隔 = max(出题冷却剩余, 随机[最小, 最大])。
        出题冷却约 1 秒（服务端已放宽；引擎自带 1.5s 配速 + 429 自动重试）。
        都填 0 = 贴着冷却下沿跑（最快，实测 5 轮 100 题仅 6 秒）；想更稳就配大一点（如 0~3000）。

设备链池（多点轮换）

      

        设备链 ks_* 是设备级凭据，原版只有 App 的设备注册才发。

        把多个来源的 ks_* 存这里 → 新登录的账号自动挑一份补齐（多份轮换，分摊风险）。

        每条设备链可以被任意多个账号指定使用（在「已导入账号」卡片的下拉里选），
        也可以放进池子里给没指定过的账号临时轮换。

        ⚠️ 所有 cookie 值在库里都是 AES-256-GCM 加密存储（密钥 data/secret.key 或 PK_SECRET）。
