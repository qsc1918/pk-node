实时日志

PK 页面（原版 H5 容器）

这是原版 PK 页面本身 —— 由服务端把 H5 整套（HTML + 资产）从 CDN 代理到本机同源， 并注入 XHR hook 把 H5 的 API 请求改写到本机，由 Node 侧补 sign / 风控头 / _productId=631 后用该账号 cookie 转发。
所以 H5 全程无感（它以为在直连主域），我们拿到了完整登录态与风控头 —— 这正是浏览器直连做不到的。

经验上报（刷分）

POST /leo-star/android/exercise/rank/login/attend（gzip + 内容编码）。
每个 ruleType 每天只记一次；实测可记账的只有 0 与 1， 单次上限 200 ⇒ 日上限 400 分。同一类型当天再报会返回 200 但不加分（服务端静默去重）。 


    


    

      
自动刷练习（出题 → 抄答案 → 提交）

      

        完整闭环：POST /leo-math/android/exams 出题（每题自带 answer）→
        PUT /leo-math/android/exams/{examId} JSON 明文提交（含笔迹 script，服务端凭笔迹判卷）。
        经验 = 答对题数 × 2（10 题 20 / 100 题 200）。

        出题冷却 ≈62 秒/账号（与 PK 同源）；引擎贴着冷却自动配速，撞频控（429）会自动重试。建议 limit=100。
      

      

        
        
        
      

      

        
        
      

      

        每轮间隔 = max(出题冷却剩余, 随机[最小, 最大])。
        出题冷却 ≈62s/账号 是硬下限，配得比它小也不会更快（会 429）；
        都填 0 = 贴着冷却下沿跑（最快）；想更稳就配大一点（如 0~10000）。

设备链池（多点轮换）

      

        设备链 ks_* 是设备级凭据，原版只有 App 的设备注册才发。

        把多个来源的 ks_* 存这里 → 新登录的账号自动挑一份补齐（多份轮换，分摊风险）。

        ⚠️ 所有 cookie 值在库里都是 AES-256-GCM 加密存储（密钥 data/secret.key 或 PK_SECRET）。
